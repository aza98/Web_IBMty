# Decision, Memory, and Complexity

Concept summaries, with applications and checks proposed by this skill. Read for navigation, catalogs, forms, comparisons, and complex tools.

## Choice Overload

Numerous alternatives that are difficult to compare can make choosing harder.

**Apply:** provide understandable filters, comparisons using relevant attributes, and groupings that help narrow candidates. Explain the basis for any recommendation.

**Limit:** there is no universal optimal number of options; an expert may need a broad catalog. Hiding options can increase effort.

**Check:** observe whether the person finds a suitable alternative and explains their choice; record abandonment and backtracking.

[Source](https://lawsofux.com/choice-overload/)

## Chunking

Organizing information into meaningful units supports processing.

**Apply:** group fields by purpose and structure content with descriptive headings. Each group should make sense to the user.

**Limit:** arbitrarily distributing elements across cards or steps does not necessarily reduce complexity.

**Check:** verify whether a piece of information can be found and assigned to its group without reading all the content.

[Source](https://lawsofux.com/chunking/)

## Cognitive Bias

Mental shortcuts can produce systematically distorted judgments, including those made by designers and researchers.

**Apply:** state assumptions and seek data that could contradict the preferred solution. Present comparisons using consistent criteria.

**Limit:** naming a bias does not diagnose an audience or establish causality. Do not use biases to induce decisions against users' interests.

**Check:** review whether research questions or selected examples favor an answer in advance.

[Source](https://lawsofux.com/cognitive-bias/)

## Cognitive Load

Understanding and operating an interface consumes mental resources; some effort comes from the task and some from its presentation.

**Apply:** eliminate redundant decisions, preserve context, and provide help where needed. Assess how much must be interpreted, remembered, and coordinated.

**Limit:** less visible content can require more memory and navigation; visual density and cognitive load are not equivalent.

**Check:** identify hesitation, rereading, errors, and information the user must remember between screens.

[Source](https://lawsofux.com/cognitive-load/)

## Hick’s Law — Hick-Hyman Law

The number and complexity of alternatives influence decision time.

**Apply:** clarify categories and labels, prioritize actions, and introduce secondary decisions when relevant. Split a task when doing so reduces total effort.

**Limit:** do not predict exact real-world task times by counting buttons; experience, search, and context matter. Do not turn every choice into another screen.

**Check:** compare decision time and errors for the same task, as well as the complete journey.

[Source](https://lawsofux.com/hicks-law/)

## Miller’s Law

Immediate memory is limited and depends on context and how information is grouped.

**Apply:** organize content by meaning and avoid requiring people to memorize values for later use.

**Limit:** the familiar 7 ± 2 does not impose a maximum number of items in menus, cards, or screens. Recognizing visible options is not equivalent to recalling them without support.

**Check:** identify what must be held mentally during the task and what can remain visible or be retained by the system.

[Source](https://lawsofux.com/millers-law/)

## Working Memory

Temporarily maintaining and manipulating information draws on limited capacity.

**Apply:** display summaries, current selections, and simultaneous comparisons. Preserve data when going back or correcting errors.

**Limit:** do not use a fixed number of items or seconds as a universal rule. Avoid filling the screen with information unrelated to the task.

**Check:** perform the journey with an interruption and observe whether it can be resumed without reconstructing decisions from memory.

[Source](https://lawsofux.com/working-memory/)

## Occam’s Razor

Among equally adequate explanations, prefer the one requiring fewer assumptions. Applied to design, this favors sufficiently simple solutions.

**Apply:** when alternatives solve the task equally well, choose the one requiring fewer concepts, exceptions, and instructions.

**Limit:** this does not establish that the interface with fewer elements is better. Preserve necessary labels, context, and controls.

**Check:** remove an element only if doing so does not impair understanding, operation, or recovery.

[Source](https://lawsofux.com/occams-razor/)

## Tesler’s Law

Some problem complexity remains and must be handled by either the system or the person.

**Apply:** automate calculations, reuse reliable data, and explain system decisions. Allow inferred values to be reviewed and corrected.

**Limit:** hiding controls does not remove the decisions they represent; automation without visibility can remove useful control.

**Check:** specify who handles each decision or calculation and how an incorrect inference is corrected.

[Source](https://lawsofux.com/teslers-law/)
